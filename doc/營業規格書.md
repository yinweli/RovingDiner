# 營業規格書

---

## 一、系統概述

本系統定義《流浪食堂 RovingDiner》營業階段的回合制規則。

一次營業是一場可被結算的遊戲流程。

玩家透過手牌與技能處理顧客。顧客會排隊、入座、行動，最後離場。

系統依照回合推進營業。推進過程會處理觸發時機、效果佇列與結算規則。

### 1. 營業目標

營業的主要目標如下：

- 處理完座位列表、排隊佇列、遊蕩列表與卡牌化列表中的所有顧客。
- 維持餐廳士氣值大於 0。
- 在回合達到上限前完成營業。

營業結束條件如下：

- **成功**：`座位列表 <= 0` 且 `排隊佇列 <= 0` 且 `遊蕩列表 <= 0` 且 `卡牌化列表 <= 0`。
- **失敗**：`回合 >= 回合上限`。
- **失敗**：`餐廳士氣值 <= 0`。

執行結算時，失敗判定優先於成功判定。

### 2. 核心流程

營業流程依下列階段推進：

- 營業開始。
- 回合開始。
- 玩家行動。
- 顧客行動。
- 回合結束。
- 營業成功或營業失敗。

玩家行動以卡牌為核心。玩家可以補牌、出牌，或手動結束行動。

顧客行動以行動佇列為核心。行動佇列由結算流程的飽食 / 耐心門檻命中與 `taskAdd` 命令填入。

回合結束時會推進效果，並執行結算。結算會處理飽食 / 耐心門檻命中（填入行動佇列）、顧客離場、餐廳滿意值、餐廳士氣值與手牌張數上限。

### 3. 核心機制

系統主要由下列機制組成：

- **卡牌**：玩家行動的主要操作單位。出牌會消耗出牌點數，並啟動卡牌實例目前持有的效果列表。
- **顧客**：營業中的處理對象。顧客以飽食值、耐心值、滿意值與士氣值參與結算。
- **技能**：效果編號列表。啟動技能時，系統依照列表順序建立並處理效果。
- **效果**：規則的主要擴充單位。效果可以立即執行，也可以進入效果佇列等待觸發或維持常駐。
- **命令**：實際改變狀態的操作。命令可修改屬性，也可執行抽牌、棄牌、移動牌堆、啟動效果等動作。

效果類型分為：

- **立即**：建立後檢查觸發條件。條件成立時執行立即命令，不進入效果佇列。
- **觸發**：進入效果佇列。指定觸發時機到達且條件成立時執行觸發命令；離開佇列時執行結束命令。
- **常駐**：進入效果佇列。加入佇列時執行啟動命令，離開佇列時執行結束命令。

效果可以使用 self 指向空物件、顧客或卡牌。當 self 失效時，相關效果會依規則清理。

### 4. 資料驅動

系統資料分為靜態表格與執行期實例。

靜態表格定義設定、座位、抽獎、卡牌、顧客、技能與效果。執行期實例保存營業狀態、卡牌狀態、顧客狀態、效果狀態與行動狀態。

卡牌、顧客與效果都以實例方式運作。因此，同一份靜態資料可以在營業中產生多個獨立狀態。

條件對象、命令對象與觸發時機共同構成資料驅動的規則介面。企劃可透過表格配置規則。程式則負責實作固定流程、效果佇列、命令解析與結算規則。

### 命名公式

- **事件 / 操作命令**：`<主體><動詞>`（事件如 `cardPlay`、`guestSeat`；命令如 `handAdd`、`effectRun`）；雙主體命令（如 `dropToDeck` / `deckToDrop`）為例外
- **命令對象集合**：`<主體 / 屬性字根><動詞>`（如 `guestPick`、`deckAll`、`samePick`、`guestWait`）；`selfSame` / `selfNear` 為例外（self 為命令對象、Same / Near 為屬性字根，無主體）
- **屬性引用**：
  - self：`<主體>.<屬性>`（如 `self.sate`）
  - 全域純屬性：無前綴（如 `morale`、`round`）；含字尾修飾時為 `<主體><字尾修飾>`（如 `roundMax`、`seatLeft`、`seatSize`）

## 三、名詞列表

- **no-op**：no operation，不執行任何操作。
- **self**：條件對象 / 命令對象的主語；指效果建立時透過目標類型選取的目標實例（顧客 / 卡牌實例），無目標時為空物件。
- **下一階段**：營業的全域屬性（字串）；指定回合內向後跳轉的目標階段，合法值 `'玩家行動'` / `'顧客行動'` / `'回合結束'` / `''`（無跳轉）。以 `phaseJump` 命令設定（不含 `''`）；階段轉移時系統自動清除為 `''`。
- **不棄卡牌**：卡牌的屬性（數值固定為 0）；鎖定計數 > 0 時該卡牌實例於「玩家手動結束」時不會棄置至棄牌牌堆。鎖定計數初值由 卡牌資料.不棄卡牌 載入（true → 1, false → 0），可被命令於執行期修改。
- **免疫閘門**：【二十、獨立流程｜啟動技能｜堆疊處理】開頭，依 `self.effectImmune` 鎖定計數擋下「`效果群組編號` 命中」的待加入效果的閘門。
- **全域屬性**：不屬於特定 self 的整體狀態屬性（如餐廳士氣值、回合）；條件式引用時不加前綴。
- **出牌點數上限**：玩家當回合可用以出牌的點數上限。
- **出牌後流放**：卡牌的屬性（數值固定為 0）；鎖定計數 > 0 時該卡牌實例於「玩家出牌」後移至流放牌堆而非棄牌牌堆。鎖定計數初值由 卡牌資料.出牌後流放 載入（true → 1, false → 0），可被命令於執行期修改。
- **出牌費用**：出牌時自出牌點數扣除的數值。
- **出牌點數**：玩家當回合可用以出牌的點數。
- **出牌點數保留**：餐廳的全域屬性（數值固定為 0）；鎖定計數 > 0 時跨回合保留 `出牌點數`（回合結束階段跳過 `出牌點數 = 0` 的清零）。
- **前置技能列表**：營業開始時逐一啟動的技能列表。
- **剩餘回合**：營業的全域衍生屬性；讀取為 `max(0, 回合上限 - 回合)`，下限夾 0。可被屬性修改命令寫入，寫入會自動轉譯為對 `回合上限` 的調整（例：`剩餘回合 = 2` → `回合上限 = 回合 + 2`、`剩餘回合 += N` → `回合上限 += N`；操作後保證 `回合上限 ≥ 回合`）。失敗仍以 `回合 >= 回合上限` 判定。
- **剩餘座位**：仍可入座的座位數。
- **卡牌化列表**：被卡牌化（全凍結保留）的顧客集合；由 `cardify` 命令移入、`restore` 命令移出。不在座位列表中，但仍視為通關條件對象（成功條件需 `卡牌化列表 <= 0`）。位於此列表的顧客進入「全凍結狀態」：屬性修改命令對其 self 屬性一律 no-op、效果佇列中 self == 該顧客的效果於 觸發 / 推進 / 清理 流程一律跳過、不被顧客類命令對象命中、不在【二十、獨立流程｜啟動技能】新選 / 隨機顧客的候選池內。
- **卡牌化還原**：由 `restore` 命令將卡牌綁定顧客自卡牌化列表移回座位列表（隨機 1 個空 seatID）並解凍其屬性與效果；無空位時 no-op。
- **卡牌群組編號**：卡牌所屬的卡牌群組編號；`0` 代表未指派群組。
- **卡牌實例**：由卡牌資料於建立初始牌堆或命令新增卡牌時實例化產生，具獨立實例編號；之後跨手牌 / 抽牌牌堆 / 棄牌牌堆 / 流放牌堆移動時保留實例身分與其狀態，抽牌本身不重新實例化。
- **卡牌技能**：卡牌資料引用的技能（綁定於卡牌資料）；卡牌實例化時以此技能的效果列表作為「實例效果列表」的初值。
- **卡牌資料**：卡牌的靜態定義，含「技能編號」與其他屬性（如「不棄卡牌」）。
- **同桌**：以【四、表格結構｜座位（Seat）表格】的 `同桌座位編號列表` 為準（含自身）。
- **命令對象**：命令執行時作用的對象；可用清單詳見【二十四、命令對象清單】。
- **啟動命令**：常駐類型效果加入效果佇列或堆疊層數增加時執行的命令。
- **回合**：當前回合數。
- **回合上限**：一場營業允許的回合上限。
- **士氣值**：顧客的屬性，生氣離場時自餐廳士氣值扣除；不可超過 `士氣值上限`，運算後超出此上限時夾為上限值。
- **士氣值上限**：顧客的屬性，士氣值的上限；建立顧客實例時自顧客資料載入，可被命令增減。
- **士氣受損**：餐廳士氣值因 `餐廳士氣值 -=` 運算而實際扣減時觸發的事件；被士氣格擋或士氣護盾完全抵消時不觸發。
- **失效對象**：self 已失效的對象，例如已離場顧客、已自本場移除（再也無法抽到）的卡牌實例、指向變身前舊實例編號的引用。
- **實例效果列表**：卡牌實例持有的效果編號列表（允許同一效果編號重複出現）；初值取自其卡牌技能，可被命令增刪。
- **實例編號**：實例（卡牌實例 / 顧客實例 / 效果實例）的唯一識別碼。
- **封印卡牌**：卡牌的屬性（數值固定為 0）；鎖定計數 > 0 時該卡牌不可出牌。鎖定計數初值由 卡牌資料.封印卡牌 載入（true → 1, false → 0）。
- **封印耐心技能**：顧客的屬性（數值固定為 0）；鎖定計數 > 0 時該顧客的耐心技能於彈出後不啟動（行動仍消費）。鎖定計數初值由 顧客資料.封印耐心技能 載入（true → 1, false → 0），可被命令於執行期修改。
- **封印閘門**：【十九、核心流程｜4. 顧客行動階段】彈出技能後，依 行動類型 查 `self.封印飽食技能` / `self.封印耐心技能` 鎖定計數決定是否啟動技能的閘門。
- **封印飽食技能**：顧客的屬性（數值固定為 0）；鎖定計數 > 0 時該顧客的飽食技能於彈出後不啟動（行動仍消費）。鎖定計數初值由 顧客資料.封印飽食技能 載入（true → 1, false → 0），可被命令於執行期修改。
- **屬性**：執行期可變的狀態容器，含 `{ 數值, 鎖定計數 }`；分全域屬性與 self 屬性兩類。實例結構詳見【五、實例結構｜數值（Value）實例】。
- **座位列表**：場上座位上的顧客集合。
- **座位編號**：座位的唯一識別碼；亦為顧客實例的欄位，指顧客占用的座位；位於遊蕩列表 / 卡牌化列表時為 0；座位列表的結算遍歷依此值由小到大排序。
- **座位表格**：靜態表，定義座位編號、所屬桌次與同桌 / 鄰桌拓樸；詳見【四、表格結構｜座位（Seat）表格】。
- **手牌**：玩家當回合可使用的卡牌實例。
- **手牌張數上限**：手牌允許的最大張數。
- **技能**：效果編號的列表（允許同一效果編號重複出現）；啟動時依此撰寫順序逐一處理。效果定義不在技能內 inline，而是位於「效果表格」。
- **技能免疫群組**：顧客的屬性（查詢函式，索引 = 技能群組編號）；`self.skillImmune(N)` 鎖定計數 > 0 時，於【二十、獨立流程｜啟動技能】顧客選取階段，當前技能群組編號 = N 者，候選排除此顧客。只能透過 `skillImmuneAdd` / `skillImmuneDel` 命令調整。
- **抽牌牌堆**：玩家的牌堆之一（內含卡牌實例）。順序以卡牌實例進入時刻為序、新進入者置於頂端、舊進入者位於底端；批次命令逐張依序進入時、頂端會呈現「最後進入者最上層」（即原批次順序的反轉）；玩家抽牌與 `deckTop[N]` 命令對象的「頂端」皆指最新進入者；洗牌時打亂整個排序。
- **抽獎群組**：抽獎表格中相同 `抽獎群組編號` 的紀錄集合；做為抽選的最小單元。群組總權重 = 0 時視為無有效紀錄、引用此群組的命令該項 no-op。
- **抽獎表格**：以抽獎群組編號分組、配置卡牌與權重的靜態抽選表格；命令引用其群組以 weighted random 選 1 個卡牌編號。
- **排隊佇列**：尚未入座的顧客所形成的佇列。
- **排隊顧客**：尚未入座、在門外排隊的顧客。
- **效果**：實際執行單位；定義於「效果表格」，具全域唯一的效果編號。
- **效果佇列**：常駐 / 觸發效果停留處理的佇列。
- **效果免疫群組**：顧客的屬性（查詢函式，索引 = 效果群組編號）；`self.effectImmune(N)` 鎖定計數 > 0 時，新建立效果群組編號 = N 的效果於 §二十 [堆疊處理] 開頭視為 no-op，已建立 / 執行中的效果不受影響。只能透過 `effectImmuneAdd` / `effectImmuneDel` 命令調整。
- **效果群組編號**：效果所屬的效果群組編號；`0` 代表未指派群組。
- **效果表格**：所有效果的中央定義表；技能 / 實例效果列表 / 命令均以效果編號引用其中的效果。
- **未出牌流放**：卡牌的屬性（數值固定為 0）；鎖定計數 > 0 時該卡牌實例於「玩家手動結束」處理剩餘手牌時必定移至流放牌堆（優先於 `不棄卡牌` 的留在手牌邏輯）。鎖定計數初值由 卡牌資料.未出牌流放 載入（true → 1, false → 0），可被命令於執行期修改。
- **條件對象**：條件運算式中被讀取以參與判斷的屬性來源；可用屬性詳見【二十三、屬性清單】。
- **棄牌牌堆**：玩家的牌堆之一（內含卡牌實例）。順序以卡牌實例進入時刻為序、新進入者置於頂端、舊進入者位於底端；批次命令逐張依序進入時、頂端會呈現「最後進入者最上層」（即原批次順序的反轉）；`dropTop[N]` 命令對象的「頂端」指最新進入者。
- **權重**：抽獎表格欄位；該筆紀錄的相對抽中機率，取值 `0~N`；同群組紀錄依權重做 weighted random 選 1 個卡牌編號。
- **流放牌堆**：玩家的牌堆之一（內含卡牌實例）。本場營業中無法被使用：補牌邏輯不從中抽出、`cardRun` 對流放牌堆卡視為位置不符 no-op。可透過 `exileToHand` / `exileToDeck` / `exileToDrop` 命令救出；本場營業結束後重置（不在本 spec 範疇）。
- **滿意值**：顧客的屬性，飽食離場時提供給餐廳滿意值；不可超過 `滿意值上限`，運算後超出此上限時夾為上限值。
- **滿意值上限**：顧客的屬性，滿意值的上限；建立顧客實例時自顧客資料載入，可被命令增減。
- **玩家**：營業的主控者；持有手牌、抽牌 / 棄牌 / 流放牌堆，於玩家行動階段抽牌、出牌與結束。
- **玩家出牌**：玩家於玩家行動階段選 1 張手牌啟動其實例效果列表的動作；詳見【十九、核心流程｜3. 玩家行動階段】。
- **玩家手動結束**：玩家於玩家行動階段主動結束行動的事件；處理剩餘手牌（依 `未出牌流放` / `不棄卡牌` 判定去向）後依 `下一階段` 進入顧客行動階段或回合結束階段。
- **生氣離場**：觸發 `exitCalm` 的離場路徑；由結算流程耐心歸 0、或 `guestExit(..., ..., 是否扣士氣=true)` 觸發；自所在容器（座位列表 / 遊蕩列表）移除並扣餐廳士氣值。
- **目標數量**：效果建立時須選取的目標數量（`1~N`）；詳見【九、目標數量】。
- **目標類型**：效果建立時是否需要選取 self、選取方式與種類；取值「無目標 / 新選顧客 / 沿用顧客 / 隨機顧客 / 新選手牌 / 沿用手牌 / 隨機手牌」，詳見【八、目標類型】。
- **立即命令**：立即類型效果於觸發條件成立時執行的命令。
- **結束命令**：觸發 / 常駐類型效果離開效果佇列或堆疊層數減少時執行的命令。
- **結束回合**：效果於效果佇列中預定離開的回合數（作用回合 = 0 時設為 0，代表整場營業保留）。
- **結算旗標**：控制「執行命令」末尾是否再次呼叫「執行結算」，避免結算遞迴。
- **編號**：資料的唯一識別碼；命名為「主體 + 編號」（如 `卡牌編號`、`顧客編號`、`技能編號`、`效果編號`、`卡牌編號`）。
- **耐心值**：顧客的屬性，關聯生氣離場；不可為負，運算後低於 0 時夾為 0。
- **耐心技能**：顧客資料.耐心技能列表中、由耐心門檻命中加入行動佇列的門檻技能；行動類型 = 耐心；於顧客行動階段彈出後啟動（受封印耐心技能閘門控制）。
- **耐心門檻**：耐心值的階段門檻線（耐心值 ≤ 門檻時觸發）。
- **行動**：行動佇列中的元素；由「顧客 + 行動類型 + 技能編號」組成（行動類型 = 飽食 / 耐心），於顧客行動階段彈出並啟動技能。
- **行動佇列**：等待結算行動的佇列。
- **行動類型**：行動的類型（飽食 / 耐心）；於顧客行動階段用以決定封印閘門查 封印飽食技能 或 封印耐心技能。
- **補牌張數上限**：玩家行動階段補牌的目標張數。
- **觸發命令**：觸發類型效果於觸發時機與觸發條件皆成立時執行的命令。
- **觸發次數**：詳見【十二、觸發次數】。
- **設定表格**：營業開始時載入全域常數（如 餐廳士氣值上限、手牌張數上限、出牌點數上限、補牌張數上限）的靜態表；詳見【四、表格結構｜設定表格】。
- **變身**：將卡牌實例 `cardID` 改為依抽獎群組 weighted random 選出的新值；同步重設實例編號（舊實例編號歸入失效對象），並依新卡牌資料載入屬性與實例效果列表。
- **遊蕩列表**：場上正在遊蕩中的顧客集合；由 `guestRoam` 移入、`guestReturn` 移出。不在座位列表中，但仍視為通關條件對象（成功條件需 `遊蕩列表 <= 0`）；耐心結算照常運作（耐心 -1、耐心 ≤ 0 仍生氣離場），飽食結算因 `self.sate` 鎖定而不會命中。顧客類命令對象（`guestAll` / `guestPick` 等）不會命中遊蕩列表中的顧客。
- **鄰桌**：以【四、表格結構｜座位（Seat）表格】的 `鄰桌座位編號列表` 為準（不含自身與同桌）。
- **桌**：座位表格中桌次編號相同的座位集合所構成的邏輯單位；不是一級實例。
- **桌次編號**：座位表格欄位；同桌次的座位視為同一桌。
- **鎖定計數**：屬性的鎖定狀態計數；> 0 時屬性視為已鎖定，一般運算對其為 no-op。
- **門檻技能**：飽食 / 耐心門檻命中時加入行動佇列的技能。
- **階段**：營業的執行階段；依序為 營業開始 / 回合開始 / 玩家行動 / 顧客行動 / 回合結束，終止時轉入 營業成功 / 營業失敗；詳見【十九、核心流程】。
- **額外發動次數上限**：卡牌的屬性；玩家出牌時額外發動次數隨機區間的上限。
- **額外發動次數下限**：卡牌的屬性；玩家出牌時額外發動次數隨機區間的下限。
- **顧客卡牌化**：由 `cardify` 命令使顧客自座位列表移至卡牌化列表的狀態；同時於玩家手牌生成 1 張綁定該顧客的卡牌（cardID = 命令指定、自動 `不棄卡牌`）；顧客進入「全凍結狀態」（詳見【三、名詞列表｜卡牌化列表】）。
- **顧客回座**：由 `guestReturn` 命令將遊蕩中的顧客移回座位列表；`剩餘座位 = 0` 時走生氣離場路徑。
- **顧客行動技能**：於「顧客行動階段」自行動佇列彈出後啟動的技能。
- **顧客資料**：顧客的靜態定義；屬性詳見【四、表格結構｜顧客（Guest）表格】。
- **顧客遊蕩**：由 `guestRoam` 命令使顧客自座位列表移至遊蕩列表的狀態；入列時 `self.sate` / `self.sateSeal` / `self.calmSeal` 鎖定計數各 + 1（飽食值不可變、飽食 / 耐心技能彈出時被封印閘門跳過）。
- **顧客離場**：觸發 `exitAny` 的離場統稱；由結算流程（飽食 / 耐心）或 `guestExit` 命令觸發；任一路徑於自所在容器（座位列表 / 遊蕩列表）移除前皆觸發 `exitAny`，依路徑可同時搭配 `exitSate` / `exitCalm`（互不互斥），移除後觸發 `exitDone`。
- **飽食值**：顧客的屬性，關聯飽食離場；不可為負，運算後低於 0 時夾為 0。
- **飽食值離場線**：顧客的屬性，飽食值達到此值時觸發飽食離場；建立顧客實例時自顧客資料載入，可被命令增減。
- **飽食技能**：顧客資料.飽食技能列表中、由飽食門檻命中加入行動佇列的門檻技能；行動類型 = 飽食；於顧客行動階段彈出後啟動（受封印飽食技能閘門控制）。
- **飽食門檻**：飽食值的階段門檻線。
- **飽食離場**：觸發 `exitSate` 的離場路徑；由結算流程飽食達線、或 `guestExit(..., 是否給滿意值=true, ...)` 觸發；自所在容器（座位列表 / 遊蕩列表）移除並提供餐廳滿意值。
- **餐廳士氣值**：餐廳的全域屬性；範圍 `0 ~ 餐廳士氣值上限`，運算後超出此範圍時夾在邊界。
- **餐廳士氣值上限**：餐廳士氣值的上限值；於營業開始時自設定表格載入，可被命令增減。
- **餐廳士氣值格擋**：餐廳的全域屬性；每 1 點抵擋 1 次「餐廳士氣值 `-=`」運算（無視扣減值），優先於餐廳士氣值護盾消耗，下限夾 0。
- **餐廳士氣值護盾**：餐廳的全域屬性；扣減「餐廳士氣值」時優先消耗，下限夾 0。
- **餐廳滿意值**：餐廳的全域屬性。

## 七、效果類型

- **立即**：不進入效果佇列；於**建立當下（目標選定後）**檢查觸發條件，符合則立即執行 立即命令，不符則直接丟棄；不會在後續觸發時機重新檢查。
- **觸發**：進入效果佇列；當觸發時機與觸發條件皆符合時，執行 觸發命令；離開佇列（作用回合結束或被移除）時執行 結束命令。
- **常駐**：進入效果佇列，以生命週期語意運作——加入佇列時執行 啟動命令，離開佇列（作用回合結束或被移除）時執行 結束命令。

## 八、目標類型

用以指定此效果建立時是否需要選取 self、選取方式與種類，包含以下項目：

- **無目標**：不須選取 self；命令中 `self` 為空物件。
- **新選顧客**：建立效果時暫停流程，等玩家手動選取顧客作為 self；每位選取的顧客各自建立一個效果，該效果的 self 即為此顧客。
- **沿用顧客**：建立效果時繼承同一啟動技能流程內前一個效果的 self；若前一個不存在、型別不符（前一個是無目標 / 手牌類），退化為「新選顧客」。
- **隨機顧客**：建立效果時系統隨機選取顧客作為 self；每位選取的顧客各自建立一個效果，該效果的 self 即為此顧客。
- **新選手牌**：建立效果時暫停流程，等玩家手動選取手牌作為 self；每張選取的手牌各自建立一個效果，該效果的 self 即為此手牌。
- **沿用手牌**：建立效果時繼承同一啟動技能流程內前一個效果的 self；若前一個不存在、型別不符（前一個是無目標 / 顧客類），退化為「新選手牌」。
- **隨機手牌**：建立效果時系統隨機選取手牌作為 self；每張選取的手牌各自建立一個效果，該效果的 self 即為此手牌。

### self 失效

- **顧客 / 手牌類型**：self 已固定後，若 self 對象失效（顧客離場、卡牌實例自本場移除），該效果失效；常駐 / 觸發效果依【二十、獨立流程｜清理效果】處理。
- **無目標類型**：self 從建立起即為空物件，命令引用 `self` 時無命令對象可作用、視為 no-op；不適用本節失效規則。

### 與命令對象的區別

目標類型與命令對象（詳見【二十四、命令對象清單】）常被混為一談，實際上位於不同層、不同時機運作：

- **目標類型**：效果規格欄位；效果建立時為該效果綁定一個 self（顧客 / 手牌 / 空物件）。屬於 **效果層** 設計。
- **命令對象**：每個命令各自指定；命令執行時解析這次要作用的對象集合。屬於 **命令層** 設計。

兩者僅在命令對象屬於 `self` 系列時才產生依賴：

- `self` / `selfNear` / `selfSame` → 以目標類型綁定的 self 為起點解析。
- 其餘命令對象（`guestAll`、`handPick`、`drawLast` …）→ 與目標類型無關，獨立解析。

思考順序建議：

1. 先決定此效果要綁什麼 self → 設目標類型。
2. 再決定每個命令要作用到誰 → 各命令各設命令對象，可選用 `self` 系列、亦可用其他來源。

進階差異（fan-out 行為）詳見【二十四、命令對象清單｜命令對象路徑 vs 目標類型路徑（區分指引）】。

## 九、目標數量

用以指定此效果建立時須選取的目標數量（`1~N`）。

- 目標類型為「無目標」「沿用顧客」「沿用手牌」時，目標數量不會起作用（取值不影響流程）。
  - 沿用類型完整繼承前一個效果的 self（可能多個），不受本次目標數量約束。
- 目標類型為「新選顧客」「新選手牌」「隨機顧客」「隨機手牌」時，目標數量代表須選取的目標數量（候選多於此數時須選滿、不得少選）；**每個選取的目標各自建立一個效果**，該效果的 self 即為此目標（1 個顧客或 1 張手牌）。
- **退化規則**（「新選XX」與「隨機XX」適用）：建立時若當前可選對象數量小於或等於「目標數量」，直接以當前可選的全部對象作為選取結果。
  - 例：目標數量 = 3、手牌僅有 2 張 → 建立 2 個效果，每個 self 各為其中 1 張手牌。
  - 例：目標數量 = 2、場上無顧客 → 不建立任何效果。

## 十、觸發時機

【十九、核心流程】中會訂定數個觸發時機，效果可於執行流程到達該時機時觸發。

- 觸發時機僅作為**時間訊號**，不攜帶任何資料；條件對象 / 命令對象均由 self 與全域屬性提供。
- 具體時機點清單詳見【二十二、觸發時機清單】。

---

## 十一、觸發條件

觸發條件採用【二十七、運算式】定義的完整運算式（含算術 + 比較 + 邏輯）。

評估失敗 → **條件不成立**（不觸發），不視為錯誤。

---

## 十二、觸發次數

觸發次數採用【二十七、運算式】定義的 `<算術式>`（不含邏輯運算）。

- 留空 → 默認 `1`
- 結果 < 0、評估失敗 → 視為 `0`
- 結果 = 0 → 視為條件不成立（不觸發、不執行命令）

每次觸發 觸發命令 連續執行 (堆疊層數 × 觸發次數) 次；結束命令 不受影響（仍只依堆疊層數）。

---

## 十三、觸發後行為

- **保留**：效果觸發後保留於效果佇列中。
- **移除**：效果觸發後從效果佇列中移除。

僅 觸發 類型適用；立即類型不進入佇列，常駐類型沒有「觸發」概念（採生命週期語意），皆不適用。

---

## 十四、作用回合

- `0`：整場營業
- `N`（>0）：持續 N 個回合（建立回合計為第 1 回合，於第 (建立回合 + N − 1) 回合的回合結束時推進移除）

立即類型不讀取此欄位（填寫 0 / N / 留空皆可），解析時忽略。

---

## 十五、作用順序

處理效果佇列相關流程時，依此值排出順序——數字越大越先執行（範圍 `0~999999`）。當作用順序相同時，再以效果編號小者優先決定先後。

啟動技能時不使用作用順序排序，依技能 / 實例效果列表的撰寫順序逐一處理。

---

## 十六、堆疊規則

堆疊層數（控制每次進行堆疊時要增加的層數，不會超過堆疊上限）：

- `0` / `1`：每次堆 1 層
- `N`（>1）：每次堆 N 層

堆疊上限：

- `0`：可堆疊，無上限
- `1`：最多 1 層（再次堆疊不會增加層數）
- `N`（>1）：可堆疊，最多 N 層

堆疊時間（控制再次堆疊時的作用回合處理方式）：

- **不變**：保留原本剩餘的作用回合
- **刷新**：重置作用回合為初始值

堆疊語意：

- **常駐類型**：每加一層執行一次 啟動命令，每退一層執行一次 結束命令。
- **觸發類型**：執行時會連續執行 N 次 觸發命令；離開佇列時連續執行 N 次 結束命令。
- 再次堆疊時，作用回合依「堆疊時間」處理（不變或刷新）。
- 已達堆疊上限時，再次堆疊**不會增加層數**（但作用回合仍依「堆疊時間」處理）。
- 再次建立效果時，需判斷是否為佇列中既有效果的同一份；同一份則執行堆疊，否則作為新效果加入佇列。

## 十七、命令

命令分為兩類，依語意採用不同語法：

### 1. 屬性修改命令

對既有屬性進行賦值或數值運算，採複合賦值語法：

```
<左值> <賦值符> [<算術式>]
```

- 左值：左值不會帶 `()`，與操作命令以此區隔。允許範圍：
  - 全域屬性：【二十三、屬性清單】主表 類別欄為「全域」且 存取欄非空者
  - 引用屬性：`<引用>.<屬性>` 寫法，其中
    - `<引用>` 為【二十三、屬性清單】主表 類別欄為「卡牌引用 / 顧客引用 / 卡牌兼顧客引用」者
    - `<屬性>` 為對應「卡牌引用屬性」/「顧客引用屬性」sub-table 存取欄非空者
- 賦值符：`=` `+=` `-=` `*=` `/=` `%=` `@` `#`（半形）
  - `=` `+=` `-=` `*=` `/=` `%=`：必帶算術式；語意同現實複合賦值（`屬性 += N` 等同「屬性 = 屬性 + N」）。
  - `@`：鎖定運算符，鎖定計數 `+= 1`；**不帶算術式**。
  - `#`：解鎖運算符，鎖定計數 `-= 1`；**不帶算術式**。對鎖定計數為 0 的屬性執行 `#` 為 no-op（不會降為負）。
  - 屬性鎖定計數 > 0 時視為已鎖定，帶值賦值（`=` `+=` `-=` `*=` `/=` `%=`）對該屬性為 no-op。
  - 鎖定 / 解鎖完全由企劃明文操控，系統不會自動清理計數；常駐效果結束時若未自行解鎖，殘留的鎖定計數會繼續保留。
- 算術式（RHS）：詳見【二十七、運算式】；可引用整數常數、全域數值屬性、`self.<屬性>`、條件對象。
- 算術評估失敗 → 本命令 no-op（不寫回、不觸發特例）。
- 運算順序：先評估算術式得到 N → 依賦值符與屬性套規則 → 結果若為小數一律四捨五入至整數 → 若屬性有範圍 clamp 則夾在邊界 → 寫回屬性。
- 引用解析語意（左值為引用屬性時）：
  - 引用解析為空物件 / 型別不符 / 屬性不存在 → 該命令 no-op
  - 鎖定計數判定（`@` / `#` / 帶值賦值的鎖定夾止）依引用所指對象套用
- 特例（餐廳士氣值 `-=`）：僅作用於全域 `morale` 左值；對引用屬性的 `-=` 走一般運算。解析得到扣減值 N 後依下列順序消耗（僅 `-=` 適用；`=` / `+=` / `*=` / `/=` / `%=` 不啟動此特例）：
  - 若 餐廳士氣值格擋 > 0 → 餐廳士氣值格擋 `-= 1`，本次無視 N，結束。
  - 否則：d = min(N, 餐廳士氣值護盾) → 餐廳士氣值護盾 `-= d` → N `-= d`。
  - 若 N > 0 → 對餐廳士氣值執行一般 `-= N` 運算，並記錄餐廳士氣值運算前後差值作為實際扣減值。
  - 若實際扣減值 > 0 → 設置 `damageValue` = 實際扣減值、`damageGuest` = 本次扣減來源顧客（無顧客來源時為空物件），觸發時機：**士氣受損**。
- 空白：忽略多餘空白

### 2. 操作命令

執行帶有參數的動作，採函式語法：

```
<命令>(命令對象, <參數1>, <參數2>, ...)
```

- 主命令括號：`(` `)`（半形）
- 命令對象帶參數括號：`[` `]`（半形）
- 參數分隔：`,`（半形）
- `命令對象` 為固定的第一個參數，必須填寫；無命令對象時填 `none`。
- 其餘參數依命令需求填入。
- **數值型參數**：採用【二十七、運算式】定義的算術式；可引用整數常數、全域數值屬性、`self.<屬性>`、條件對象。
- 算術評估失敗 → **整個動作 no-op**（單一參數失敗即放棄整個命令）。
- varargs（可變數量 trailing 參數）：命令尾端依命令定義可接 0 ~ M 個額外參數（如 `handCopy` 的附加效果編號）。
- 空白：忽略多餘空白
- **命令對象帶參數**：當命令對象本身帶參數（如 `handPick[N, 卡牌編號]`、`deckTop[N]`），使用 `[` `]` 區隔；整個帶 `[...]` 的命令對象視為第一參數的一個 token；命令對象內部的 `,` 為其本身參數分隔，不與外層 `,` 衝突；**命令對象內部的數值參數同樣採算術式**。

#### 命令對象（第一參數）

可用命令對象詳見【二十四、命令對象清單】。

`self` / `selfSame` / `selfNear` 於效果建立時即固定，後續執行皆使用此固定的命令對象；其他命令對象於每次執行時重新解析。

「指定 xxx」中斷規則、退化規則、filter 規則詳見【二十四、命令對象清單】。

### 3. 範例

#### 屬性修改命令

- `攻擊力 = 10`
  → 攻擊力設為 10
- `血量 += 5`
  → 血量加 5
- `防禦力 *= 2`
  → 防禦力乘以 2
- `攻擊力 += self.sate / 2`
  → 攻擊力加「self.sate 的一半」（算術式內含 self 屬性 + 整數除法四捨五入）
- `morale -= self.score * 2`
  → 餐廳士氣值扣「self.score 的兩倍」，觸發 `-=` 特例（依格擋 → 護盾 → morale 順序消耗）
- `攻擊力 @`
  → 鎖定攻擊力於當前值
- `攻擊力 #`
  → 解除攻擊力鎖定（保留當前值）
- `damageGuest.sate += damageValue`
  → 把本次士氣受損值加到肇事顧客的飽食值（damage 時機；無顧客來源時 damageGuest 為空 → no-op）
- `drawLast.cardSeal @`
  → 把最近抽進手牌的卡牌封印

#### 操作命令

- `deckToHand(deckTop[2], false)`
  → 從抽牌牌堆頂端取 2 張加入手牌（不洗牌）；deck 不足且 drop 有卡時自動洗牌補回
- `handAdd(none, 10031, 1)`
  → 依卡牌編號 10031 實例化 1 張新卡牌加入手牌
- `deckToHand(deckTop[drawMax - 2], false)`
  → 從抽牌牌堆頂端取「補牌張數上限 - 2」張加入手牌（算術參數含全域屬性）
- `deckToHand(deckTop[self.sate / 2 + 1], false)`
  → 從抽牌牌堆頂端取「self.sate 一半 + 1」張加入手牌（算術參數含 self 屬性）
- `guestSpawn(none, 顧客編號, exitLastSeat)`
  → 在最後離場座位產生指定顧客（算術參數含全域屬性）
- `phaseJump(none, '玩家行動')`
  → 跳轉至玩家行動階段（字串字面值 `'玩家行動'`）
- `deckToHand(deckTop[energy / 0], false)`
  → 算術評估失敗（除 0）→ 整個 deckToHand 不執行
- `taskAdd(self, '飽食', 30001)`
  → 將「self（顧客）+ 行動類型 飽食 + 技能編號 30001」加入行動佇列尾端
- `cardEffectAdd(handPick[1, 0], 20042)`
  → 對玩家所選 1 張手牌實例（任意編號），於其實例效果列表加入 1 個效果編號 20042
- `cardEffectDel(self, 20042)`
  → 對 self（限 self 為卡牌實例時）的實例效果列表，移除 1 個效果編號 20042（卡上無此編號視為 no-op）
- `cardEffectDelAll(dropRand[1, 0], 20042)`
  → 對棄牌牌堆中隨機 1 張卡牌實例（任意編號）的實例效果列表，移除全部效果編號 20042

具體命令項目將於後續訂定。

## 十九、核心流程

### 1. 營業開始階段

```
營業開始設置 {
  從設定表格載入全域設定
  設置 回合 = 0
  設置 結算旗標 = false
  設置 出牌點數 = max(出牌點數, 出牌點數上限)
  清空累積抽牌 / 棄牌 / 出牌 / 流放張數（4 個多重集合）
  從外部資料建立排隊佇列
  從外部資料建立抽牌牌堆（依卡牌資料實例化為卡牌實例）
  從外部資料建立前置技能列表
  其他...
}

foreach 該技能 in 前置技能列表 {
  啟動技能：該技能
}

觸發時機：**營業開始**
進入回合開始階段
```

### 2. 回合開始階段

```
回合準備設置 {
  設置 回合 += 1
  設置 所有「回合 X」事件型屬性 = 0
}

觸發時機：**回合準備**

回合開始設置 {
  設置 出牌點數 = max(出牌點數, 出牌點數上限)
  其他...
}

觸發時機：**回合開始**

while 剩餘座位 > 0 && 排隊佇列 > 0 {
  設置 該顧客 = 從排隊佇列彈出 1 位
  將該顧客加入座位列表
  設置 最後入座顧客 = 該顧客
  設置 回合入座人數 += 1
  觸發時機：**顧客入座**
}

switch 下一階段 {
case '顧客行動': 
  清除 下一階段
  進入顧客行動階段

case '回合結束': 
  清除 下一階段
  進入回合結束階段

default:
  清除 下一階段
  進入玩家行動階段
}
```

### 3. 玩家行動階段

```
while 手牌 < 補牌張數上限 && (抽牌牌堆 + 棄牌牌堆) > 0 {
  if 抽牌牌堆 <= 0 {
    將棄牌牌堆隨機洗牌後移至抽牌牌堆（此時棄牌牌堆應為空）
  }

  從抽牌牌堆抽 1 張卡牌加入手牌
}

觸發時機：**玩家開始**

while true {
  if 下一階段 ∈ {'顧客行動', '回合結束'} {
    視為 玩家結束 事件
  }

  switch 玩家事件 {
  case 玩家出牌 該卡牌:
    if 該卡牌.封印卡牌 鎖定計數 > 0 {
      不執行出牌（卡牌封印）
    } else if 該卡牌.cardify != none && 剩餘座位 == 0 {
      不執行出牌（卡牌化卡無空位）
    } else if 出牌點數 >= 出牌費用 {
      設置 出牌點數 -= 出牌費用
      設置 最後出牌卡牌 = 該卡牌
      設置 回合出牌張數 += 1
      設置 額外次數 = 在 [該卡牌.額外發動次數下限, 該卡牌.額外發動次數上限] 範圍內隨機取整數（下限 > 上限 || 上限 < 0 時為 0）

      重複 (1 + 額外次數) 次 {
        啟動技能：**實例效果列表**
      }

      if 該卡牌.cardify != none {
        執行 restore(該卡牌)（系統自動還原綁定顧客）
      }

      if 該卡牌.出牌後流放 鎖定計數 > 0 {
        從手牌移除該卡牌加入流放牌堆
      } else {
        從手牌移除該卡牌加入棄牌牌堆
      }

      觸發時機：**玩家出牌**
    } else {
      不執行出牌
    }

  case 玩家結束:
    觸發時機：**玩家結束**

    foreach 該卡牌 in 剩餘手牌 {
      if 該卡牌.未出牌流放 鎖定計數 > 0 {
        移至流放牌堆
      } else if 該卡牌.不棄卡牌 鎖定計數 == 0 {
        棄置至棄牌牌堆
      } else {
        留在手牌
      }
    }

    switch 下一階段 {

      清除 下一階段
      進入回合結束階段

  }
}
```

## 二十、獨立流程

### 啟動技能

啟動技能流程的輸入為效果列表與技能群組編號：

- **效果列表**：一份效果編號列表。典型來源為一個 named 技能；卡牌打出時則為該卡牌實例當前的效果列表。
- **技能群組編號**：顧客選取時用作 `skillImmune(N)` 的索引（排除該群組免疫的顧客）。來源依呼叫情境：
  - 卡牌出牌：卡牌資料.技能.技能群組編號
  - 顧客行動：行動.技能.技能群組編號
  - 前置技能：該技能.技能群組編號
  - 無對應來源：0

流程內部依效果編號查「效果表格」取得對應的效果定義後處理。

```
啟動技能(效果列表, 技能群組編號) {
  設置 沿用來源 = 空集合

  while true {
    if 效果列表 <= 0 {
      結束啟動技能
    }

    設置 該效果 = 從效果列表彈出 1 個

    switch 該效果.目標類型 {
    case 無目標:
      設置 本次 self 集合 = [空物件]
      設置 沿用來源 = 空集合

    case 新選顧客 | 新選手牌:
      候選對象 filter：
        顧客類：限定座位列表（自動排除遊蕩列表 / 卡牌化列表），再排除 self.skillImmune(技能群組編號) > 0 者
        手牌類：限定手牌（無額外 filter）
      依【九、目標數量】退化規則決定選取結果；不適用退化時暫停流程讓玩家選滿 目標數量 個對象
      設置 本次 self 集合 = 選取結果
      設置 沿用來源 = 本次 self 集合

    case 隨機顧客 | 隨機手牌:
      候選對象 filter：
        顧客類：限定座位列表（自動排除遊蕩列表 / 卡牌化列表），再排除 self.skillImmune(技能群組編號) > 0 者
        手牌類：限定手牌（無額外 filter）
      依【九、目標數量】退化規則決定選取結果；不適用退化時系統隨機選 目標數量 個對象
      設置 本次 self 集合 = 選取結果
      設置 沿用來源 = 本次 self 集合

    case 沿用顧客 | 沿用手牌:
      設置 本次 self 集合 = 沿用來源（依【八、目標類型】沿用規則；沿用來源不變）
    }

    foreach self in 本次 self 集合 {
      switch 該效果.效果類型 {
      case 立即:
        if 觸發條件成立 {
          執行 立即命令
        }

      case 觸發:
        套用 [堆疊處理]

      case 常駐:
        套用 [堆疊處理]

        if 實際增加層數 > 0 {
          執行 啟動命令
        }
      }
    }
  }
}
```

### [堆疊處理]

```
堆疊處理(self, 待加入效果) {
  if self 為顧客 && self.effectImmune(待加入效果.效果群組編號) > 0 {
    no-op（不建立、不堆疊、不執行啟動命令）
    設置 實際增加層數 = 0
    return
  }

  if 由 effectRun 命令呼叫 && 參數 N > 0 {
    設置 本次增加層數 = N
  } else {
    設置 本次增加層數 = 待加入效果.堆疊層數（0 / 1 視為 1）
  }

  設置 既有效果 = 從佇列找出與待加入效果同份者
                  （效果編號相同 && self 對象相同；無目標的 self 為空物件，視為彼此相同）

  if 既有效果 不存在 {
    設置 新效果.層數 = min(本次增加層數, 堆疊上限)

    if 待加入效果.作用回合 == 0 {
      設置 新效果.結束回合 = 0
    } else {
      設置 新效果.結束回合 = 當前回合 + 作用回合 - 1
    }

    加入效果佇列
    設置 實際增加層數 = 新效果.層數
  } else {
    設置 增加前層數 = 既有效果.層數
    設置 既有效果.層數 = min(既有效果.層數 + 本次增加層數, 堆疊上限)
    設置 實際增加層數 = 既有效果.層數 - 增加前層數

    switch 待加入效果.堆疊時間 {
    case 不變:
      既有效果.結束回合 維持原值

    case 刷新:
      if 待加入效果.作用回合 == 0 {
        設置 既有效果.結束回合 = 0
      } else {
        設置 既有效果.結束回合 = 當前回合 + 作用回合 - 1
      }
    }
  }
}
```

### 觸發時機

```
觸發時機(時機) {
  設置 觸發列表 = 從效果佇列篩選（效果類型 = 觸發 && 觸發時機 = 時機）
  觸發列表 依「作用順序、效果編號」排序
              （作用順序大者優先；同作用順序時效果編號小者優先）

  while true {
    if 觸發列表 <= 0 {
      結束觸發時機
    }

    設置 該效果 = 從觸發列表彈出 1 個

    if 該效果.觸發條件 不成立 {
      continue
    }

    設置 本次 self 集合 = 該效果.self 集合（啟動技能時已決定）

    設置 該效果中止 = false
    foreach self in 本次 self 集合 {
      設置 M = 評估 self.觸發次數

      if M <= 0 {
        設置 該效果中止 = true
        break
      }

      重複 (該效果.堆疊層數 × M) 次 {
        執行 該效果.觸發命令
      }
    }

    if 該效果中止 {
      continue
    }

    if 該效果.觸發後行為 == 移除 {
      重複 該效果.堆疊層數 次 {
        執行 該效果.結束命令
      }

      從效果佇列移除 該效果
    }
  }
}
```

```
  }
}
```

### 執行結算

本流程「所有顧客」涵蓋 座位列表（座位編號）與 遊蕩列表（順序無關）；遊蕩列表中的顧客因 `self.sate` 鎖定不會命中飽食門檻 / 飽食離場，但耐心門檻 / 生氣離場照常運作（耐心技能於彈出時被 `self.calmSeal` 封印閘門跳過）。

```
執行結算() {
  設置 結算旗標 = true

  套用 [終止判定]

  foreach 該顧客 in 所有顧客 {
    foreach 門檻 in 該顧客.飽食門檻列表（由低到高） {
      if 該顧客.飽食值 >= 門檻.門檻值 && 門檻 不在 該顧客.已觸發飽食門檻 {
        將 門檻 加入 該顧客.已觸發飽食門檻
        將「該顧客 + 對應門檻技能」加入行動佇列（行動類型 = 飽食）
      }
    }
  }

  foreach 該顧客 in 所有顧客（飽食值 >= 飽食值離場線） {
    設置 最後離場顧客 = 該顧客
    設置 最後離場座位 = 該顧客.seatID
    設置 回合離場人數 += 1
    觸發時機：**顧客離場**
    觸發時機：**飽食離場**
    從所在容器（座位列表 / 遊蕩列表）移除該顧客
    觸發時機：**顧客離場後**
    清理效果(該顧客)
    設置 餐廳滿意值 += 該顧客.滿意值
  }

  套用 [終止判定]

  foreach 該顧客 in 所有顧客 {
    foreach 門檻 in 該顧客.耐心門檻列表（由高到低） {
      if 該顧客.耐心值 <= 門檻.門檻值 && 門檻 不在 該顧客.已觸發耐心門檻 {
        將 門檻 加入 該顧客.已觸發耐心門檻
        將「該顧客 + 對應門檻技能」加入行動佇列（行動類型 = 耐心）
      }
    }
  }

  foreach 該顧客 in 所有顧客（耐心值 <= 0） {
    設置 最後離場顧客 = 該顧客
    設置 最後離場座位 = 該顧客.seatID
    設置 回合離場人數 += 1
    觸發時機：**顧客離場**
    觸發時機：**生氣離場**
    從所在容器（座位列表 / 遊蕩列表）移除該顧客
    觸發時機：**顧客離場後**
    清理效果(該顧客)
    以該顧客作為 damageGuest，設置 餐廳士氣值 -= 該顧客.士氣值
  }

  套用 [終止判定]

  if 手牌 > 手牌張數上限 {
    暫停流程，等玩家手動選擇手牌逐張棄置至棄牌牌堆，直到 手牌 <= 手牌張數上限
  }

  設置 結算旗標 = false
}
```

### [終止判定]

失敗優先於成功，命中則立即跳出結算進入對應階段。

```
[終止判定]() {
  if 回合 >= 回合上限 || 餐廳士氣值 <= 0 {
    設置 結算旗標 = false
    進入營業失敗階段
  } else if 排隊佇列 <= 0 && 座位列表 <= 0 && 遊蕩列表 <= 0 && 卡牌化列表 <= 0 {
    設置 結算旗標 = false
    進入營業成功階段
  }
}
```

## 二十一、流程補充

### 前置技能的撰寫約束

此階段啟動前置技能時，**座位列表與手牌皆為空**。【八、目標類型】規定 `self` / `selfSame` / `selfNear` 於效果建立時即固定、不隨後續場況更新（退化規則下會直接不建立效果），因此撰寫前置技能時建議：

- **建議使用「無目標」**：此時座位列表與手牌皆空，若目標類型選 新選顧客 / 新選手牌 / 隨機顧客 / 隨機手牌 / 沿用顧客 / 沿用手牌（沿用會退化為新選），當前無可選對象，依退化規則不會建立任何效果。
- **欲操作後續才出現的顧客或手牌**：請以「觸發效果」掛載至適當觸發時機（如 `顧客入座`、`手牌補充` 等），並於 立即 / 觸發 / 啟動 命令內使用動態命令對象（`全部顧客`、`隨機顧客`、`指定手牌` 等）取得當下命令對象。
- **可直接於開場進行的操作**：修改全域屬性、加入卡牌至抽牌牌堆或棄牌牌堆等不需引用 `self` 的命令。

### 卡牌技能的撰寫提醒

玩家出牌流程中，**啟動實例效果列表時該卡牌實例仍位於手牌**，待啟動完成後才移至棄牌牌堆。因此：

- `全部手牌` / `隨機手牌` / `指定手牌` 等命令對象會將「正在打出的這張卡牌實例」列入候選，若不希望命中自身需自行排除。
- 若需以「打出後」的手牌狀態為基準，可改用觸發效果掛載至 `玩家出牌` 時機（該時機卡牌實例已移入棄牌牌堆）。
- 實例效果列表的內容可能已被命令增刪過（與卡牌資料引用的卡牌技能不一定相同），啟動時以卡牌實例當下的內容為準。

### 結算補充

- **self 失效**：顧客離場 / 卡牌自本場移除後，立即執行清理效果（詳見【二十、獨立流程｜清理效果】）。
- **行動佇列**：由本流程的飽食 / 耐心門檻步驟動態填充，於「顧客行動階段」彈出消費。
- **時機 context 過濾**：飽食 / 生氣時機為全局訊號；若效果想表達「自己離場時觸發」，需於觸發條件寫 `self == exitLast`。士氣受損時機可用 `damageGuest` / `damageValue` 取得來源顧客與實際扣減值。其他事件型時機（入座 / 抽牌 / 出牌 / 顧客行動等）比照 `最後入座顧客`、`最後抽出卡牌`、`最後出牌卡牌`、`最後行動顧客` 等屬性，詳見【五、實例結構｜營業（Game）實例】。

### 凍結語意

位於卡牌化列表的顧客 A 進入「全凍結狀態」，作用範圍：

- **屬性凍結**：屬性修改命令（`= / += / -= / *= / /= / %= / @ / #`）作用於 `self == A` 時一律 no-op — 耐心值 / 飽食值 / 滿意值 / 士氣值 / 各上限 / 各封印計數通通不變。
- **效果凍結**：效果佇列中 self == A 的效果於【觸發時機】【推進效果】【清理效果】流程一律跳過（不觸發、結束回合不推進、不清理）；A 不視為失效對象。
- **技能凍結**：A 不在【執行結算】「所有顧客」涵蓋範圍內，飽食門檻 / 耐心門檻不會命中，不會加入行動佇列 — 飽食技能 / 耐心技能自然不發動。
- **指令隔離**：A 不被顧客類命令對象（`guestAll` / `guestPick` / `guestRand` / `nearXxx` / `sameXxx`）命中；也不在【二十、獨立流程｜啟動技能】新選 / 隨機顧客的候選池內。

進入 / 退出由 `cardify` / `restore` 命令控制；解凍時對 A 身上所有 結束回合 > 0 的效果，結束回合 += (當前回合 - A.freeze)，使凍結期間不消耗作用回合。

- **參數規則**：表中參數欄非空的命令對象必須帶完整參數（無預設值）；裸寫無參數版視為語法錯誤。
- **顧客類命令對象解析範圍**：`guestAll` / `guestPick` / `guestRand` / `nearPick` / `nearRand` / `samePick` / `sameRand` 解析時僅取**座位列表**中的顧客，不命中遊蕩列表 / 卡牌化列表；`guestWait` 僅取排隊佇列。
- **`selfSame` / `selfNear` 邊界規則**：`self` 非顧客時，`selfSame` / `selfNear` 視為空集合。
- **N 規則**：
  - N > 0：取 N 張；候選 <= N 退化取全部（`Pick` 不彈介面）；候選 > N 時 `Pick` 暫停玩家挑、`Rand` 隨機抽
  - N = 0：空集合
  - N < 0：
    - `Rand`：隨機保留 abs(N) 張、其餘取出；候選 <= abs(N) → 取出為空集合
    - `Pick` / `Top`：視為空集合
  - `Pick` 暫停時玩家不可取消、必須選出。
- **filter 規則**（`handXxx` / `deckXxx` / `dropXxx`）：卡牌編號 = `0` 視為任意（無 filter）；卡牌編號 = X 視為「位於該牌堆 / 手牌且 `self.cardID == X`」者。
- **`deckTop` auto-shuffle 規則**：
  - deck >= N → 取頂端 N 張
  - deck < N 且 deck + drop >= N → 先將棄牌牌堆隨機洗牌移至抽牌牌堆 → 再取頂端 N 張
  - deck + drop < N → 取全部（drop 仍洗進 deck）
  - `deckTop` 是唯一在解析時會修改狀態的命令對象（承接舊 `deckToHandN` 的補牌語義）；其他命令對象一律只讀。

### 命令對象路徑 vs 目標類型路徑（區分指引）

兩條路徑都可對 N 個對象作用，但語義不同：

| 路徑             | 寫法                                                     | 行為                                                          |
|:-----------------|:---------------------------------------------------------|:--------------------------------------------------------------|
| **目標類型路徑** | 新選 / 隨機 XX + 目標數量 = N                            | 建立 **N 個獨立 effect**，各自 self、各自進效果佇列、各自堆疊 |
| **命令對象路徑** | 無目標 + 命令對象 `XxxPick / Rand / Top / All`（帶參數） | 建立 **1 個 effect**，命令在執行時對 N 個對象 fan-out         |

撰寫指引：

- 「每個目標各自疊層 / 各自結束 / 各自需要進入效果佇列」→ 目標類型路徑
- 「一次性地對 N 個對象批次施作（無獨立生命週期）」→ 命令對象路徑

### cardRun 處理流程

對命令對象的每張卡牌實例依序執行（不限於手牌；可為手牌 / 抽牌牌堆 / 棄牌牌堆中的卡牌實例；流放牌堆的卡視為位置不符 → 該項 no-op）：

1. 封印閘門 `self.cardSealLock > 0` → no-op
2. 消耗點數 = true 且 出牌點數 < 出牌費用 → no-op
3. 消耗點數 = true → 出牌點數 - 出牌費用
4. 設置 最後出牌卡牌 = 該卡牌、回合出牌張數 + 1
5. 啟動其實例效果列表
6. 進棄牌堆 = true → 從原位置移至棄牌牌堆（該卡牌已在棄牌牌堆者 no-op）
7. 觸發 **玩家出牌**

### copy / clone 處理流程

對命令對象的每張卡牌實例（source）依序執行：

1. 依複製類型實例化 N 張新卡：
   - **copy（淺複製）**：新卡的 `cardID` = source.cardID；屬性（出牌費用 / 不棄卡牌 / 封印卡牌 / 出牌後流放 / 未出牌流放 / 額外發動次數下限 / 額外發動次數上限 含鎖定計數）與實例效果列表載入卡牌資料初始值
   - **clone（深複製）**：新卡的 `cardID` = source.cardID；屬性（出牌費用 / 不棄卡牌 / 封印卡牌 / 出牌後流放 / 未出牌流放 / 額外發動次數下限 / 額外發動次數上限 含鎖定計數）與實例效果列表深複製 source 當前狀態
   - **卡牌化來源顧客**：copy / clone 皆設為 `none`（不沿用 source 綁定，避免兩張卡綁同一顧客）
   - 實例編號：每張新卡重新生成（不沿用 source 的實例編號）
2. 附加效果編號（命令尾端 `,` 分隔的可變數量 trailing 參數，0 ~ M 個）— 對每張新卡的實例效果列表附加所列效果編號
3. 將每張新卡加入目的地（hand / deck / drop / exile）；對應的 system-level 觸發（`cardDraw` / `cardDrop` / `cardExile`）與屬性更新（`drawLast` / `drawCount` 等）由系統自動處理

附加效果編號為命令尾端的 varargs 參數，省略表示不附加。例如：

- `handCopy(handPick[1, 0], 3)` — 淺複製 3 份至手牌、不附加效果
- `handCopy(handPick[1, 0], 3, 20042)` — 同上、每張新卡附加效果 20042
- `handCopy(handPick[1, 0], 3, 20042, 20055)` — 每張新卡附加效果 20042 + 20055

### 變身處理流程

對命令對象的每張卡牌實例（source）依序執行：

1. 抽獎：依抽獎群組編號從抽獎表格 weighted random 取出 1 個卡牌編號作為新 cardID（群組總權重 = 0 → 該項 no-op）
2. 設置 source.cardID = 新 cardID
3. 重新分配 source 的實例編號（舊實例編號 → 失效對象）
4. 依新卡牌資料載入 source 的 出牌費用 / 不棄卡牌 鎖定計數 / 封印卡牌 鎖定計數 / 實例效果列表
5. 立即執行清理效果（處理舊實例編號殘留於效果佇列的效果）
6. 設置 `morphLast` = source、`morphOldID` = 舊 cardID、`morphNewID` = 新 cardID、`morphCount` + 1
7. 觸發時機：**卡牌變身**

source 自身停留在原牌堆位置；不觸發 `cardDraw` / `cardDrop` / `cardExile`。

### guestExit 處理流程

對命令對象的每位顧客依序執行：

1. 設置 `exitLast` = 該顧客、`exitLastSeat` = 該顧客.seatID、`exitCount` + 1
2. 觸發時機：**顧客離場**（`exitAny`）
3. 是否給滿意值 = true → 觸發時機：**飽食離場**（`exitSate`）
4. 是否扣士氣 = true → 觸發時機：**生氣離場**（`exitCalm`）
5. 從所在容器（座位列表 / 遊蕩列表）移除該顧客
6. 觸發時機：**顧客離場後**（`exitDone`）
7. 將該顧客視為失效對象並執行清理效果
8. 是否給滿意值 = true → `餐廳滿意值 += 該顧客.滿意值`
9. 是否扣士氣 = true → 以該顧客作為 `damageGuest` 執行 `餐廳士氣值 -= 該顧客.士氣值`（走【十七、命令｜1. 屬性修改命令】之餐廳士氣值 `-=` 特例）

### guestReturn 處理流程

對命令對象的每位顧客依序執行（限位於遊蕩列表者；其他位置該項 no-op）：

1. `self.sate` / `self.sateSeal` / `self.calmSeal` 鎖定計數各 - 1（解鎖入列時的自動鎖）
2. 當 `剩餘座位 > 0`：
   - 自遊蕩列表移除該顧客
   - 加入座位列表尾端（不觸發 `guestSeat`）
3. 當 `剩餘座位 = 0`：
   - 走 `guestExit(該顧客, false, true)` 流程（自步驟 1 開始）

### guestSpawn 處理流程

依參數依序判斷（顧客資料不存在 → 整體 no-op）：

1. **座位編號 = 0**（產生遊蕩中顧客）：
   - 依顧客編號實例化 1 位新顧客
   - 將新顧客 `self.sate` / `self.sateSeal` / `self.calmSeal` 鎖定計數各 + 1（與 `guestRoam` 自動鎖一致；維持「位於遊蕩列表 ↔ 三項屬性鎖定」不變式）
   - 加入遊蕩列表
2. **座位編號 = N（N > 0）**（產生座位顧客）：
   - 當 N 不存在於座位表格中、或 `座位列表` 中已有 seatID = N 的顧客 → no-op
   - 否則：依顧客編號實例化 1 位新顧客、設置新顧客 `seatID = N`、加入座位列表
3. **其他取值（N < 0）**：no-op

典型用法：搭配 `exitDone` 觸發時機 + 全域屬性 `exitLastSeat` 接續離場顧客的座位 — 如「顧客離場招喚」效果於 `exitDone`（顧客已自所在容器移除後）觸發 `guestSpawn(none, 顧客編號, exitLastSeat)`，自座位離場者沿用原座位、自遊蕩離場者沿用遊蕩態（`exitLastSeat = 0`）。

### cardify 處理流程

對命令對象的每位顧客依序執行（顧客不在座位列表 / 卡牌資料不存在 → 該項 no-op）：

1. 自座位列表移除該顧客
2. 加入卡牌化列表
3. 設置 該顧客.freeze = 當前回合
4. 依卡牌編號實例化 1 張新卡牌 C（屬性 / 實例效果列表載入卡牌資料初始值）
5. 設置 C.cardify = 該顧客
6. C 的「不棄卡牌」鎖定計數 + 1
7. C 加入手牌

### restore 處理流程

對命令對象的每張卡牌實例依序執行（`self.cardify = none` / `剩餘座位 = 0` → 該項 no-op）：

1. 設 A = self.cardify
2. A 自卡牌化列表移除
3. A.seatID = 座位列表中**隨機 1 個空 seatID**；A 加入座位列表
4. 對效果佇列中 self == A 且 結束回合 > 0 的效果，結束回合 += (當前回合 - A.freeze)
5. A.freeze = 0
6. self.cardify = none
7. self 的「不棄卡牌」鎖定計數 - 1

## 二十七、運算式

本章定義 spec 所有「運算式」共用語法，作為【十一、觸發條件】+【十二、觸發次數】+【十七、命令】的共用 SSOT。

以現實運算式規則為基礎，含下列遊戲專有設計：

- 邏輯詞 `AND` `OR` 不區分大小寫（非 `&&` `||`）。
- 一元否定 `!`。
- 屬性鎖定 / 解鎖 `@` `#`（僅【十七、命令｜1. 屬性修改命令】最外層使用、不出現在算術式內）。
- 算術中間值可為小數（含小數字面值與 `+` `-` `*` `/` `%` 結果），運算過程不四捨五入；最終值由呼叫方寫回屬性時統一四捨五入（詳見【十七、命令｜1. 屬性修改命令】運算順序）。
- 四捨五入採 half-away-from-zero：`2.4` → `2`、`2.5` → `3`、`-2.4` → `-2`、`-2.5` → `-3`。
- 評估失敗不拋錯，以「評估失敗狀態」回傳；後續行為由呼叫方各自定義。

### 1. 文法（BNF）

```
<運算式>       ::= <邏輯或> [? <運算式> : <運算式>]
<邏輯或>       ::= <邏輯且> {OR <邏輯且>}
<邏輯且>       ::= <否定> {AND <否定>}
<否定>         ::= [!] <否定>
                 | <比較>
<比較>         ::= <算術式> [<比較符> <算術式>]
<比較符>       ::= < | > | <= | >= | == | !=
<算術式>       ::= <項> {(+ | -) <項>}
<項>           ::= <因子> {(* | / | %) <因子>}
<因子>         ::= - <因子>
                 | <字面值> | <條件對象> | <內建函式> | ( <運算式> )
<條件對象>     ::= <屬性> | <查詢函式> | <引用屬性> | <引用查詢函式> | self
<屬性>         ::= <屬性名>
<查詢函式>     ::= <屬性名>( <參數列表> )
<內建函式>     ::= <內建函式名>( <算術式> {, <算術式>} )    // <內建函式名> 詳見【二十六、內建函式清單】
<引用屬性>     ::= <引用名>.<屬性名>
<引用查詢函式> ::= <引用名>.<屬性名>( <參數列表> )
<引用名>       ::= self | <物件引用名>     // <物件引用名> 詳見【二十三、屬性清單】類別欄
<參數列表>     ::= <參數> [, <參數>]*
<參數>         ::= <算術式> | <字串>
<字面值>       ::= <整數> | <小數> | <字串> | <布林> | <空物件>
```

`{…}` 表示零次以上重複（左結合），`[…]` 表示可選。`+ - * / %` 與 `AND` `OR` 皆採左結合；三元 `? :` 採右結合，且僅評估被選中的分支。文法分層即優先順序（見本章第 3 節）：`AND` 緊於 `OR`、一元 `!` 緊於 `AND`；`<因子>` 開頭的 `-` 為一元負號（如 `-morale`、`-(2 + 3)`）。

### 2. 運算符

| 類別              | 運算符                          | 備註                                                                 |
|:------------------|:--------------------------------|:---------------------------------------------------------------------|
| 算術 (arithmetic) | `+` `-` `*` `/` `%`             | 中間值可為小數；運算過程不四捨五入；最終值由呼叫方寫回時統一四捨五入 |
| 比較 (comparison) | `<` `>` `<=` `>=` `==` `!=`     | 物件引用比較：`==` / `!=` 比實例編號；空物件只與空物件相等           |
| 邏輯 (logical)    | `!`（一元）/ `AND` `OR`（二元） | `AND` `OR` 不區分大小寫                                              |
| 分組 (grouping)   | `(` `)`                         | 邏輯 / 算術任一層級皆可；parser 依位置決定意義                       |
| 三元 (ternary)    | `? :`                           | 條件成真選真值分支、成假選假值分支；只評估被選中的分支；右結合       |

### 3. 優先順序（precedence，由高到低）

1. 括號 (grouping)：`(` `)`
2. 乘除取餘 (multiplicative)：`*` `/` `%`
3. 加減 (additive)：`+` `-`
4. 比較 (comparison)：`<` `>` `<=` `>=` `==` `!=`
5. 否定 (NOT)：`!`
6. 邏輯且 (AND)：`AND`
7. 邏輯或 (OR)：`OR`
8. 三元 (ternary)：`? :`（右結合）

### 4. 字面值（literal）

| 類型           | 寫法                 | 範例                       |
|:---------------|:---------------------|:---------------------------|
| 整數 (integer) | 直接書寫             | `5`、`-3`、`100`           |
| 小數 (decimal) | 直接書寫             | `1.5`、`0.25`、`-0.5`      |
| 字串 (string)  | 以單引號 `'…'` 包夾 | `'玩家行動'`、`'顧客行動'` |
| 布林 (boolean) | 不區分大小寫         | `true`、`false`、`TRUE`    |
| 空物件 (none)  | 不區分大小寫         | `none`、`NONE`             |

### 5. 條件對象（屬性 / 查詢函式 / 引用屬性 / 引用查詢函式 / self）

引用 spec 中可讀取的值，四類來源：

1. **屬性**：全域屬性名（如 `morale`、`round`、`drawCount`）。
2. **查詢函式**：全域查詢函式（如 `tableCount('>=', 2)`、`handSize(2)`）。
3. **引用屬性 / 引用查詢函式**：以物件引用為主體加 `.<屬性名>` 或 `.<屬性名>( ... )`（如 `drawLast.cardID`、`drawLast.cardGroup`、`self.calm`、`taskGuest.score`、`self.effectStack(101)`）；可用屬性集為【二十三、屬性清單】中對應引用型別的「卡牌引用屬性 / 顧客引用屬性」表所列。
4. **`self`**：可單獨作為引用使用，與其他物件引用使用 `==` / `!=` 比較。

可用條件對象詳見【二十三、屬性清單】；查詢函式語意詳見 §9。

引用為空物件 / 型別不符 → 該存取評估失敗（依呼叫方規則）。

### 6. 「省略比較符」的布林判定

`<比較>` 只寫單一算術式（無比較符）時：

- 結果為非 0 數值 → 真
- 結果為 0 → 假
- 結果為非數值（字串 / 布林 / 物件引用）→ 評估失敗

### 7. 評估失敗條件

| 失敗條件         | 觸發場景                                                                                                              |
|:-----------------|:----------------------------------------------------------------------------------------------------------------------|
| 條件對象解析失敗 | 引用不存在的全域屬性 / 與 self 型別不符 / self 未固定                                                                 |
| 除 0 / 取餘 0    | 算術式 `/0` 或 `%0`                                                                                                   |
| 非數值參與算術   | 字串 / 布林 / 物件引用 出現在算術式中（除 0 / 取餘 0 視為「除 0 / 取餘 0」處理）                                      |
| 比較跨型別       | 比較符兩側型別不符（數值 vs 字串 / 數值 vs 物件引用 / 字串 vs 物件引用 等）；物件引用 vs 物件引用為合法（比實例編號） |
| 三元條件失敗     | 三元 `? :` 條件位置評估失敗 → 整個三元失敗（兩分支皆不評估）；條件成功時，未被選中的分支即使會失敗也不影響整體       |

### 8. 評估失敗的回傳狀態

本節不規定後續行為，由呼叫方各自定義：

- 【十一、觸發條件】→ 條件不成立（不觸發）
- 【十二、觸發次數】→ 視為 `0`
- 【十七、命令｜1. 屬性修改命令】→ 該命令 no-op
- 【十七、命令｜2. 操作命令】→ 該動作 no-op

### 9. 查詢函式

帶參數的條件對象，語法為 `<屬性名>( <參數列表> )` 或 `self.<屬性名>( <參數列表> )`。可用查詢函式詳見【二十三、屬性清單】。
